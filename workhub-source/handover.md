# WorkHub 업무 양식: 인수인계 문서

다음 AI 에이전트와 개발자를 위한 문서입니다. **코드를 수정하기 전에 끝까지 읽어 주세요.**

## 1. 무엇을 만드는가

사내 포털 SASOHAN WorkHub의 게시판 영역에 들어갈 기능입니다. 직원이 개발자 없이 업무 기록 양식을 직접 만들고, 내역을 쌓고, 변경 이력을 남깁니다.

성격은 스프레드시트보다 Airtable에 가깝습니다. 열마다 입력 유형과 필수 여부가 정해져 있고, 내역은 폼으로 입력합니다.

**이 폴더는 프로토타입입니다.** 서버, 로그인, 권한, 공유 데이터가 없습니다. 목표는 이 코드를 그대로 배포하는 것이 아니라, 이 동작을 실제 WorkHub에 구현하는 것입니다.

## 2. 대상 환경

| 항목 | 내용 | 근거 |
|---|---|---|
| 프레임워크 | Next.js App Router + React (추정) | 기존 게시판 HTML의 `_next/static`, `app/(app)/board/page` |
| 스타일 | Tailwind + 자체 `kit-*` 클래스와 토큰 (추정) | `bg-surface`, `text-ink-3`, `kit-tnum` 등 |
| 아이콘 | lucide (추정) | `lucide-*` 클래스 |
| DB·API·인증 | **알 수 없음** | 이 폴더에 정보 없음 |

추정 항목은 작업 전에 실제 저장소에서 확인해 주세요. 기존 WorkHub에 컴포넌트나 패턴이 있으면 그것을 우선합니다. 이 프로토타입의 바닐라 JS 구조를 따라 할 필요는 없습니다.

**UI 기준:** 기존 비품 구매 게시판(`/board?board=supply`)입니다. 이 프로토타입의 색상 값은 브랜드 초록(`#2f9e63`, `#186a44`)에서 추정한 것이므로 실제 토큰으로 교체합니다.

- `workhub-preview.html`: 같은 코드를 한 파일로 묶은 결과물. 코드 이해에는 `workhub-source/`를 보세요.

## 4. 반드시 유지할 규칙

사용자가 직접 확정한 내용입니다. 임의로 바꾸지 마세요.

**데이터**

1. 데이터는 실제로 지우지 않습니다. 내역, 줄, 항목 삭제는 모두 soft delete입니다.
2. 변경 이력은 영구 보존합니다. 수정·삭제 기능을 만들지 않으며, 서버에서도 막습니다.
3. 내역은 항상 등록 번호 1개 + 줄 1개 이상입니다. 한 줄짜리 내역도 줄 1개로 저장합니다.
4. 항목 값은 모두 줄에 저장합니다. 단일 값과 여러 줄 값을 나눠 이중 저장하지 않습니다.
5. 등록일(`createdAt`)은 최초 저장 시각입니다. 입력·수정할 수 없고, 내역을 수정해도 바뀌지 않습니다.

**줄마다**

6. `field.multi`는 입력 화면만 결정합니다. 저장된 데이터는 변환하지 않습니다.
7. 언제든 켜고 끌 수 있으며 막지 않습니다. 저장 시점부터 적용합니다.
8. 꺼도 기존의 여러 줄은 그대로 표시합니다. 기존 줄은 수정·삭제할 수 있지만 줄을 추가할 수 없습니다. 새 내역은 입력칸 1개입니다.

**표**

9. 등록 번호는 내역당 하나이며, 다른 단일 입력 항목과 함께 줄 수만큼 병합합니다.
10. 모든 줄을 전부 표시합니다. "밥 외 1건" 같은 줄임과 행 안의 내역별 요약은 금지입니다. 긴 글도 말줄임 없이 줄바꿈합니다.
11. 등록일 열은 따로 없습니다. 등록 번호 값을 누르면 모든 행이 등록일로 바뀌고, 다시 누르면 돌아옵니다. 열 제목은 항상 "등록 번호"입니다.
12. 상세 창은 데이터 값을 눌렀을 때만 열립니다. 셀의 빈 배경으로는 열리지 않습니다.
13. 수정과 삭제는 행 단위이며 정렬·필터와 겹치지 않도록 별도의 관리 열에 둡니다. 삭제에는 확인 절차가 필요합니다.

**필터**

14. 기간 필터의 기준은 사용일 같은 입력 항목이 아니라 등록일입니다.
15. 구성은 기존 게시판과 같습니다: 기간 버튼(전체, 오늘, 최근 7일, 이번 달, 올해), 직접 지정(`260404` 입력과 달력), 검색어.

**양식 설정**

16. 항목명, 유형, 필수, 줄마다, 순서, 드롭다운 선택 항목에 더해 양식 이름과 설명도 양식 설정에서 수정합니다.
17. 미리보기는 줄마다가 켜져 있으면 항상 두 줄로 보여 줍니다.

## 5. 데이터 구조

```js
board = {
  name, desc,
  fields: [{ id, name, type, required, multi, active, options }],
  records: [{
    id,          // 등록 번호. max(id) + 1이며 삭제된 내역도 포함해 재사용하지 않음
    createdAt,   // 'YYYY.MM.DD HH:mm', 기존 내역은 null 가능
    deleted, deletedAt,
    lines: [{
      lineId,    // 내부 값. 화면에 표시하지 않음
      deleted, deletedAt,
      [field.id]: value  // 항목 값
    }]
  }],
  history: [{ time, who, title, detail }]
}
```

- `field.type`: `date`, `number`, `text`, `select`, `upload`
- `active: false`: 삭제되어 숨긴 항목. 값은 유지합니다.
- 값은 `field.id`로 연결하므로 항목 이름을 바꿔도 유지됩니다.
- 실제 DB에서는 양식, 항목, 내역, 줄, 이력 테이블로 나누는 구성을 권장합니다. 다만 줄 값을 어떻게 저장할지(JSON 또는 EAV)는 항목이 동적이므로 개발 시 결정이 필요합니다.

예시:

```
#1026
 ├ lineId a1: 항목 = 밥,   금액 = 5000
 └ lineId a2: 항목 = 커피, 금액 = 2000
#1027
 └ lineId b1: 항목 = 택시, 금액 = 12000
```

## 6. 교체하거나 버릴 것

| 현재 프로토타입 | 실제 구현 |
|---|---|
| `localStorage` 저장 (`workhub-prototype-v1`) | 서버 DB |
| `IndexedDB` 첨부파일 (`workhub-local-files-v1`) | 서버 업로드와 저장소, 용량·형식 제한, 접근 권한 |
| 작성자 `관리자 (예시)` 고정 | 로그인 사용자 |
| 브라우저 시각의 `createdAt`, 이력 시각 | 서버 시각 |
| 브라우저에서 계산하는 다음 번호 | 서버 발급. 동시 등록 시 중복 금지 |
| 가짜 포털 헤더, 사이드바의 기존 게시판 항목 | 기존 WorkHub 공통 레이아웃 |
| 예시 데이터, `sampleCreatedAt`, `PROTOTYPE` 표시 | 제거 |
| `migrateBoard()` | 실제 데이터가 없으면 제거 |

**실제 연동이 아닌 코드입니다. 옮기지 마세요.**

- `window.openai`, `setWidgetState`, `modelContent`, `privateContent`, `openai:set_globals`: 이전 도구에서 남은 저장 연결부.
- `globalThis.Tweak`: 동작하지 않는 코드.
- `dev-notes.js`와 `.dn-*` 스타일: 인수인계용 메모 핀. 내용을 읽은 뒤 실제 서비스에는 넣지 않습니다.

## 7. 구현 전에 사용자에게 확인할 것

아직 정해지지 않았습니다. **추측해서 만들지 말고 물어봐 주세요.**

1. **권한:** 양식 만들기, 양식 설정, 내역 작성·수정·삭제를 각각 누가 할 수 있는가.
2. **표 하단 합계:** 지금은 숫자 항목의 합계를 표시합니다. 사용자가 "가격이 아닐 수도 있다"고 지적해 제거 여부를 확인 중입니다. 제안은 합계를 빼고 건수만 남기는 것입니다.
3. **삭제 후 관리:** 삭제된 내역과 숨긴 항목을 보거나 복구하는 화면이 필요한가.
4. **확정 후 잠금:** 비품 구매처럼 확인 완료 후 수정·삭제를 막는 규칙이 필요한가. 표에서 바로 상태를 바꾸는 기능도 필요한가.
5. **양식 관리:** 양식 자체의 삭제 기능, 사이드바에서의 위치.
6. **페이지 나눔:** 내역과 이력이 많아질 때의 처리. 프로토타입에는 없습니다.
7. **유형 변경 경고:** 값이 있는 항목의 유형을 바꿀 때 경고가 필요한가. 지금은 경고 없이 값을 유지합니다.
8. **엑셀 다운로드, 소속 필터:** 비품 구매에는 있지만 이번 요청에는 포함되지 않았습니다.

## 8. 알려진 동작과 한계

- 검색은 화면 표시 값 기준입니다. `90,000`은 찾지만 `90000`은 찾지 못합니다. 서버 검색으로 옮길 때 정해 주세요.
- 줄마다 항목은 첫 번째 값으로 정렬합니다. 내역은 줄 단위로 나뉘지 않습니다.
- 카드 사용 내역 예시의 #1020~1023 `createdAt`은 임의의 값입니다.
- 옛 `items` 값은 줄로 옮겼고 원본도 데이터에 남아 있습니다. 화면에서는 쓰지 않습니다.
- 동시 편집 충돌 처리는 없습니다.

**직접 검증하지 못한 부분**

- 실제 파일 선택기를 사용한 첨부파일 업로드.
- 달력 버튼을 눌렀을 때 뜨는 날짜 선택 창. 오류는 없었지만 창을 눈으로 확인하지 못했습니다.
- 값을 드래그해 복사할 때 상세 창이 열리지 않는 동작.
- `file://`로 직접 열었을 때의 동작. 테스트는 로컬 서버에서 했습니다.

자동화된 테스트 코드는 없습니다. 위 검증은 브라우저에서 수동으로 진행했습니다.

## 9. 완료 전 확인 항목

- [ ] 내역, 줄, 항목을 삭제해도 DB에 값이 남고, 이력이 기록된다.
- [ ] 이력을 수정·삭제할 API가 없다.
- [ ] 한 줄짜리 내역도 줄 1개로 저장된다.
- [ ] 줄마다를 껐다 켜도 데이터와 표시가 그대로다.
- [ ] 줄마다를 끈 뒤 기존 여러 줄이 그대로 보이고, 새 내역은 입력칸 1개다.
- [ ] 등록 번호를 누르면 모든 행이 등록일로 바뀌고, 열 제목은 그대로다.
- [ ] 값을 누르면 상세가 열리고, 셀 빈 곳을 누르면 열리지 않는다.
- [ ] 기간 필터는 입력 항목이 아니라 등록일을 기준으로 한다.
- [ ] `createdAt`, 번호, 이력 시각을 서버에서 만든다.
- [ ] 저장하지 않은 변경은 닫거나 이동하기 전에 확인한다.
